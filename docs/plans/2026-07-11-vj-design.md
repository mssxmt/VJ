# VJ — Gantz Graf-style Browser VJ Audio Visualizer: Design

Date: 2026-07-11
Status: Approved

## Goal

An open-source (MIT) browser-based VJ tool inspired by Autechre's "Gantz Graf" video:
an abstract procedural machine that convulses in sync with audio. Full audio input,
MIDI controller support, keyboard control, and a fully automatic mode.

## Requirements

- Audio input: mic/line-in (getUserMedia) and local audio file playback
- Procedural "imaginary machine" objects: swap (regenerate), add, remove parts via parameters
- Adjustable effects (glitch etc.), audio-reactive
- Camera control: manual and auto
- Everything can run in AUTO mode
- MIDI controller support with MIDI-learn assignment
- Keyboard shortcuts

## Tech Stack

- Vite + React 19 + TypeScript
- three + @react-three/fiber + @react-three/drei
- @react-three/postprocessing (postprocessing)
- zustand (UI/parameter state)
- Web Audio API (AnalyserNode; no external audio lib)
- Web MIDI API (Chrome/Edge)
- Vitest for unit tests

## Architecture

```
src/
├─ audio/    AudioEngine: input sources (mic / file), FFT analysis
│            Features: band energies (low/mid/high), RMS, onset detection (spectral flux)
├─ scene/    R3F scene, procedural machine generator
├─ effects/  Postprocessing chain (Glitch, ChromaticAberration, Bloom, Pixelation, Scanline, Noise)
├─ camera/   Camera rig (manual OrbitControls + auto cuts/dolly/shake)
├─ control/  Parameter registry — the central abstraction
└─ ui/       Hideable overlay panel (tabs: Machine / Effects / Camera / Audio / MIDI)
```

### Parameter registry (core design decision)

Every controllable parameter (machine config, effect intensity, camera params, auto toggles)
is registered centrally with `id / label / range / default / group`. All four control surfaces
bind through this registry:

- UI sliders/toggles
- MIDI learn (select param in UI → move a knob → CC mapped; persisted to localStorage, JSON export/import)
- Keyboard shortcuts
- AUTO mode modulators (LFO + audio features driving registered params)

### Audio reactivity data flow

Audio features are written each frame into a mutable `AudioFrame` object and read directly
inside R3F `useFrame` — never through React state — to keep 60fps. Onset (transient)
detection is the core of the Gantz Graf feel: onsets trigger machine deformation,
part swaps, camera cuts, and glitch bursts.

### Procedural machine

- Primitive parts: box clusters, pipes, fins, antennas, rings, greeble
- Seeded random assembly into a part tree
- Parameters: seed, complexity, part count, symmetry, scale distribution
- "Swap" = regenerate with new seed; "add/remove" = part count/type params
- Per-part audio-reactive behaviors: scale punch on onset, rotation on mid,
  emissive flash on high, vertex glitch displacement
- InstancedMesh for performance

### Effects

Each effect intensity = manual value + audio-reactive amount blend.

### Camera

Manual: OrbitControls + parameters. Auto: cuts on onsets, LFO-driven dolly/shake.

### AUTO mode

Global toggle + per-section (machine / effects / camera) toggles.

### Keyboard defaults

Numbers = machine regenerate/presets, letters = effect toggles, H = hide UI,
F = fullscreen, Space = AUTO toggle, arrows = camera.

## Testing

Vitest TDD for pure logic: parameter registry, audio feature extraction (synthetic
waveform input), machine generator seed determinism, MIDI mapping logic.
Rendering: minimal smoke tests only.

## Out of scope (v1)

Tab/display audio capture, recording/export, preset sharing, WebGPU/TSL renderer.
